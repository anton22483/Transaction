# Проект: ETL-конвейер аналитической банковской системы (Клиенты, Счета, Транзакции)

Инженерный проект по проектированию реляционной структуры базы данных в СУБД PostgreSQL и автоматизации загрузки банковских логов (ETL-процесс) из сырых CSV-выгрузок с помощью Python (Pandas + SQLAlchemy). 

## Стек технологий
* **СУБД:** PostgreSQL 
* **Язык конвейера:** Python 3 (Pandas, SQLAlchemy, psycopg)
* **Инструмент администрирования и визуализации:** DBeaver CE
* **Методология:** 3NF (Третья нормальная форма), обеспечение целостности данных (Data Integrity)

---

## 🗄️ 1. Архитектура и ограничения базы данных

Реляционная структура данных спроектирована по правилам 3NF с жесткой валидацией входящих бизнес-данных на уровне СУБД с помощью ограничений `CHECK` и обеспечением ссылочной целостности:

* **`clients` (Клиенты)** — содержит уникальный ID клиента, дату регистрации, регион и тип клиентского сегмента. Настроен `CHECK` на валидность сегментов (*Mass, Premium Bronze/Premium Silver/Premium Gold/Premium Diamond, Private*).
* **`accounts` (Счета)** — привязаны к клиентам со связью **1:M (Один ко многим)**. Реализовано каскадное удаление `ON DELETE CASCADE`. Введен `CHECK` на разрешенные типы счетов (*Дебетовый, Накопительный, Кредитный, Инвесткопилка*).
* **`transactions` (Транзакции)** — хранит историю операций по счетам (связь **1:M**). Финансовые суммы защищены типом данных с фиксированной точностью `DECIMAL(15, 2)`, предотвращающим ошибки округления. Категории расходов валидируются через `CHECK` (*Супермаркеты, Рестораны, Транспорт, Развлечения, Зарплата, Переводы*).

## 2. Автоматизация конвейера (ETL на Python)

Скрипт автоматизирует миграцию данных, решая проблему несовместимости типов (`DatatypeMismatch`), когда даты из CSV считываются как текст.

### Логика работы скрипта:
1. **Extract (Извлечение):** Пошаговая загрузка сырых банковских выгрузок из локальной директории `data/` с помощью `pandas.read_csv()`.
2. **Transform (Трансформация):** Преобразование строковых представлений дат в бинарный формат времени СУБД с помощью `pd.to_datetime()` для столбцов `registration_date`, `open_date` и `transaction_date`.
3. **Load (Загрузка):** Пакетная безопасная запись обработанных датафреймов в целевые таблицы PostgreSQL через метод `.to_sql(if_exists='append')` с использованием пула соединений SQLAlchemy.

## 3. Структура файлов и локальный запуск

Репозиторий структурирован согласно лучшим практикам ведения ИТ-проектов:
* **`Script-9.sql`** — DDL-скрипт создания структуры таблиц, первичных/внешних ключей и ограничений `CHECK`.
* **`loader.ipynb`** (или `.py`) — Python-конвейер загрузки и приведения типов данных.
* **`data/`** — директория с исходными сырыми файлами (`clients.csv`, `accounts.csv`, `transactions.csv`).
* **`image.png`** — сгенерированная в DBeaver ER-диаграмма связей.

### Порядок развертывания:
1. Выполнить скрипт `Script-9.sql` в DBeaver для создания пустой архитектуры.
2. Разместить файлы данных в папку `data/`.
3. Запустить Python-скрипт для миграции данных в СУБД.
